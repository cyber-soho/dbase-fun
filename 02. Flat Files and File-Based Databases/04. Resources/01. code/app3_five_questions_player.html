How the code works — step by step

  1. The first statement creates orders_flat from read_csv with the delimiter, quote and header stated and store_rejects = true; the malformed line 11 goes to reject_errors, 11 rows are loaded.
  2. Q1a filters on the text '2026-11-21' and finds 7 lines; Q1b lists both spellings of the date and finds 8. The difference is the two date formats of Lesson 1.
  3. Q2 compares lower(city) with 'madrid', so Madrid, MADRID and madrid all match: 8 lines.
  4. Q3 computes round(unit_price * quantity, 2) AS line_total, sorts by the alias in descending order and keeps 3 rows. ORDER BY can use the alias because it runs after SELECT.
  5. Q4 returns each payment method once with DISTINCT; the empty payment method of M505-1046 appears as one NULL row.
  6. Q5a shows that quantity = NULL is never true (0 rows); Q5b uses IS NULL and finds M505-1045.
  7. The final comment gives the SQL Server form: SELECT TOP 3 … ORDER BY … DESC.
  8. In the player: Start runs the clauses in logical order, Pause stops after the current clause, Step advances one clause, Restart clears the window. The logical-order bar shows where the query is.
