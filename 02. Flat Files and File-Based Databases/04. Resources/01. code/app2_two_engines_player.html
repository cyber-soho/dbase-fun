Two engines, one export (Python: sqlite3 + duckdb)

TaskA Python script that loads the same export into SQLite, one sale per transaction as the stall tablet does, and into DuckDB, read in place as the Monday report does; it reads one order back, shows type affinity versus strict types, records the malformed line in reject_errors, answers one analytical question and lists the two database files.

How the code works — step by step

  1. Lines 2–9 import csv and os from the standard library, sqlite3 (part of Python) and duckdb (installed with pip).
  2. Lines 11–15 delete stall.sqlite and mercadillo.duckdb if an earlier run left them, so every run starts empty.
  3. Lines 17–19 connect to stall.sqlite, which creates the file, and create a table of four columns. There is no server, port or password.
  4. Lines 21–31 read the export with csv.DictReader, skip the malformed line (its extra value sits under the key None) and insert each valid sale with ? placeholders, committing after every insert as the tablet does.
  5. Lines 33–35 count the 11 rows and read one order back by its identifier: the typical small read.
  6. Lines 37–45 insert the text 'two' into the INTEGER column: typeof() reports text (type affinity). The test row is deleted and the connection closed; the file remains.
  7. Lines 47–55 connect to mercadillo.duckdb. The automatic guess finds 1 column; the read_csv call with delim, quote, header and store_rejects finds 13.
  8. Lines 57–61 create orders_flat from read_csv (11 rows) and print reject_errors: line 11 appears with CAST and TOO MANY COLUMNS.
  9. Lines 63–69 try to insert 'two' into the BIGINT column quantity: DuckDB raises a Conversion Error.
  10. Lines 71–73 answer an analytical question (8 Madrid lines in any spelling) and close the connection.
  11. Lines 75–77 list the two files and their sizes: 8,192 bytes for SQLite (two 4 KB (kilobyte) pages) and 536,576 bytes for DuckDB (space reserved in 256 KB blocks).
  12. In the player: Start, Pause, Step, Restart and Copy work as in Example 1; the execution window keeps every line and every printed result.
